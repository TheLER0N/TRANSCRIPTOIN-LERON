# TASK.md

Назначение: задать активный этап и порядок доведения GUI до релиза 1.

## Текущий этап

Этап 1: рабочий GUI, инструменты и блок-схемы.

## Порядок работ

1. Маршрутизация ввода: одно поле, режимы `Проект`, `Схема`, `Без контекста`.
2. Исполнение инструментов: `read_files`, `write_files`, `list_dir`, `grep`, `finish`.
3. Обработка недоступных функций: явный отказ, список доступных инструментов, альтернатива или `finish`.
4. Блок-схемы: создание ИИ, редактирование пользователем, валидация узлов и связей.
5. Полный GUI-тест: сборка, прогон, отчёт, ручные сценарии.

## Чек-лист

1. Удалить дублирующие окна и поля отправки в `MainWindow`.
2. Подключить чтение файлов внутри проекта без карточки подтверждения.
3. Проверить, что режим `Схема` использует только явно прикреплённую схему.
4. Проверить валидацию схемы: уникальные `id`, непустые метки, связи только к существующим узлам, без самосвязей.
5. Сохранить отчёт теста в `logs` с временем, статусом и ошибками.

## Критерии приёмки

1. `ВЕРДИКТ: PASS` в полном GUI-тесте.
2. Ручной сценарий отправки: сообщение уходит из одного поля в каждом режиме.
3. Ручной сценарий файлов: агент читает файл внутри проекта и продолжает без запроса подтверждения.
4. Ручной сценарий схемы: ИИ собирает схему без ошибок, пользователь редактирует узел/связь без ошибок GUI.
5. Недоступная функция возвращает понятное сообщение и не подвешивает чат.
